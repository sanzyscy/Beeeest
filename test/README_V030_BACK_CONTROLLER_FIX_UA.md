# STRUMYK SPORTS v0.30 — виправлення «Назад» після DRM-плеєра

**Стан:** окрема експериментальна версія. **22.11.2026.**

## Відтворена проблема за скріншотом і поясненням користувача

У встановленій Lampa Uncensored на Android, стартова сторінка **HTTPS** (`https://bylampa.online/`), демовідео ClearKey DASH у STRUMYK v0.29 справді відтворювалося понад 1:36. Але при натисканні **«Назад» саме з нашого тестового плеєра** з'являлася велика зелена помилка:

```
TypeError: Cannot read properties of null (reading 'destroy')
at extensions.onBack
(https://bylampa.online/app.min.js?v=1994804:36299:18)
```

Це стек із **ядра Lampa**, а не помилка `dash.js`, `player.setProtectionData()` або декодування відео. Ймовірна причина — активний контролер `extensions`, який має посилання на `extensions.onBack` після закриття/знищення менеджера розширень. Відкритий вихідний код Lampa показує `extensions.onBack = () => { extensions.destroy(); extensions = null; ... }` **без перевірки**, чи `extensions` ще не `null`. На конкретній зібраній `app.min.js` послідовність подій не простежено; немає доказу, що плагін сам обнуляє `extensions`.

Окрема проблема в STRUMYK v0.29: `focusController()` робив `L.Controller.toggle('content')` без `force`; стандартна Lampa може перенаправити це перемикання через стек відкритих вікон, залишивши невідповідний активний контролер.

## Що виправлено без втручання в ядро Lampa

В окремому `test/strumyk_plugin_v030_back_controller_fix_test.js`:
1. **Після відкриття екрана STRUMYK** його контролер `content` реєструється й активується через `L.Controller.toggle('content', true)`. Це вимикає перенаправлення на колишній контролер із віконного стека Lampa.
2. `focus()` виконує вузький guard `recoverFromStaleExtensionsController()` — **лише якщо** екран STRUMYK активний, контролер називається `extensions`, але **у DOM немає відкритого вікна `.extensions`**. Тоді відновлює `content` із параметром `force=true`.
3. При закритті демо `closeDrmDemo()`: зупиняє власний DASH-плеєр, повертає екран діагностики, після чого перевіряє stale-контролер.
4. `L.Select.onBack`: примусово повертається до `content`, а не залишає керування застарілому віконному контролеру.
5. Жодного перехоплення всіх натискань Android Back, патча Lampa core `extensions`, обходу DRM, змін у відеоплеєрі, HTTP-парсері чи UI-контейнері.

**Це захисне виправлення плагіна, не виправлення дефекту ядра Lampa.** Якщо менеджер розширень із null-об'єктом знову стає активним із іншого місця, там можливий аналогічний збій. Безпечне виправлення ядра — перевірка актуальності об'єкта перед `destroy()` плюс коректне зняття stale `onBack`.

## Перевірка на Android

1. Залишити HTTPS-стартову адресу Android Lampa. Вимкнути v0.29, повністю закрити Lampa й запустити знову. Встановити **тільки v0.30**.
2. STRUMYK → ⚙ → DASH/DRM → **Демовідео ClearKey DASH**, натиснути `▶ Запустити тест`. Перевірити, що відео грає.
3. Натиснути **«‹ Назад» угорі всередині STRUMYK**. Має показатися екран «DASH / DRM діагностика», **без зеленої помилки**.
4. Повторити запуск, натиснути **фізичну/Android-системну кнопку «Назад»** або кнопку нижньої панелі Lampa. Результат має бути той самий. Перевірити по черзі, не натискати двічі дуже швидко.
5. Перевірити закриття через «✕ Закрити», а тоді Back з екрану діагностики.
6. Якщо помилка залишилась — зняти скріншот, указати **яку саме кнопку** натиснуто. Не треба чистити налаштування Lampa й перевстановлювати APK.

## Перевірки перед випуском тесту

- JS синтаксис: **PASS**.
- Мок: `extensions` активний, вікна розширень немає → перемикання `content,true`: **PASS**.
- Мок: `extensions` активний та вікно реально є → не втручаємося: **PASS**.
- Мок: `content` уже активний → нічого не змінюємо: **PASS**.
- `focusController()` реєструє штатний `content` та робить `toggle(content,true)`: **PASS**.
- Раніше перевірений публічний DRM-демо код, автономні спортивні API, EPG, UI v0.29 — **збережені**.
- Фактичний Back у Lampa Uncensored v0.30: **ще не перевірений на пристрої**.

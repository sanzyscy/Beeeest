# STRUMYK — фактична робота плеєра за `strumyk-app.js` (22.11.2026)

## Джерело
Користувач завантажив оригінальний файл `strumyk-app.js`, 50 687 байтів, 772 рядки. Аналіз виконаний без здогадок про поведінку вкладених провайдерних скриптів; сам вихідний JS **не публікуємо в репозиторії**.

## Доведено завантаженим JS

- Сторінка паралельно завантажує `SK.api.L`, `SK.api.J`, `SK.api.X`, `SK.api.M`, необов'язково `SK.api.O` через `fetch(...,{credentials:'same-origin'})`; далі збирає події з **J→O→M→X→L**, і якщо `BY_ID[id]` уже є, **повністю відкидає дубль**. v0.22 у Lampa експериментально об'єднує додаткові `_embeds` із дублікатів — це не точна копія семантики сайту, а розширення, яке **не гарантує працездатності** додаткових провайдерів.
- Вибір доступних джерел виконується із `event._embeds`; розділення мова/канал за `|`. Порядок мов визначає `SK.settings.langOrder`, а якість — `SD < HD < FHD < UHD/4K`. При відкритті матчу сайт вибирає **перший доступний embed після сортування**; не перевіряє його HTTP-статус перед показом.
- `setPlayer(url)` **створює HTML-елемент `iframe`**, передає URL із `embed` без перетворень, `allow='fullscreen; encrypted-media; autoplay; picture-in-picture'`, `referrerPolicy='no-referrer-when-downgrade'`, без `sandbox`. Зміна джерела з кнопки `.src-btn` просто викликає `setPlayer(data-src)`.
- Старт сторінки матчу: URL `/#<ID>`, підхоплюється `hash` і `openEvent(BY_ID[id])`. Перехід із Lampa за `/#ID` у v0.21+ відповідає маршрутизації сайту.
- У цьому файлі **немає** `hls.js`, `.m3u8`, `.mpd`, `MediaSource`, пошуку HLS або виклику VLC/MX. Це означає лише, що створення відеопотоку винесено за межі **цього** JS; не доводить, що HLS/DRM відсутні чи доступні у провайдерному iframe.
- У JS **немає автоматичного резервного переходу на інше джерело після 403/404**. Він переключає джерело тільки після натискання кнопки користувачем.

## Наслідки для Lampa
- Працездатний WEB-iframe на сайті != доступний прямий медіоманіфест для Lampa Player / VLC / MX Player.
- Політика `Referer` сама по собі **не може зробити Lampa сторінкою походження `strumyk.ca`**. Успішна внутрішня рамка Strumyk і зовнішній iframe усередині Lampa можуть отримувати різний контекст запиту. Надіслати довільний `User-Agent` недостатньо, щоб довести доступ до відеосегментів.
- Виявлена користувачем `404` для `/e/vip/...` поза сайтом не доводить, що сайт у той самий момент використав саме цю адресу з тим самим режимом запиту. Потрібно **порівняти реально вибраний `.src-btn[data-src]` і фактичний `#player iframe.src` під час успішного відтворення**.
- `v0.23` захищає інтерфейс від мертвої вебсторінки, але нативний відеоплеєр ще не доведено. Не називати новий JS релізом «відео працює», допоки не перевірено звук/кадри в Lampa Player та окремо VLC/MX.

## Одноразовий аналіз у працюючому Chrome

Скрипт `tools/strumyk_sport_player_trace_v024.js` призначений для запуску **після відкриття та реального відтворення матчу на strumyk.ca**, бажано на раніше проблемному матчі або його поточному аналогу. Він:
- знімає `data-src` активної кнопки, поточний `iframe.src` та їх рівність, без значень URL-query;
- фіксує, чи дозволений доступ до DOM iframe із поточної сторінки (same-origin);
- у разі доступу до DOM виводить тільки метадані мережевих ресурсів HLS/DASH/плеєра, не самі маніфести чи токени;
- робить два знімки з інтервалом 4,5 сек, зберігає локальний `STRUMYK_SPORT_PLAYER_V024_....json`;
- не виконує мережевих запитів, не змінює відео, не зберігає cookies або значення підписів.

**Важливо:** якщо iframe чужого домену, доступ до його внутрішніх мережевих запитів із головної сторінки заборонений Same-Origin Policy. У такому разі потрібен окремий законний спосіб доступу до провайдерного відео (або сайт-плеєр як запасний варіант), а не вигадана HLS-адреса.

# STRUMYK SPORTS v0.22 — об'єднання та оновлення відеоджерел

**Стан:** тестовий автономний JS-плагін для Lampa/Lampa Uncensored. Не є підтвердженим рішенням для відтворення. Створено на основі v0.21; робочі v0.14, v0.19, v0.20, v0.21 не змінювалися.

## Чому ця версія

Код попередніх версій `parseStrumykApiBundle` збирав події в порядку `J→O→M→X→L`, але за повторного `id` **ігнорував увесь запис**, зокрема його додаткові `_embeds`. Це могло приховувати частину доступних мов/каналів/варіантів якості для вже знайденого матчу.

Зі скріншотів користувача: `Vancouver Canucks — Minnesota Wild` відтворюється після відкриття події на головній сторінці Strumyk. У v0.20 наявний `Premier Sports 1` WEB-embed `/e/vip/...` повертав HTTP 404 за прямого відкриття й під час HTTP-пошуку. **Наявність відео на головній сторінці не доводить, що цей конкретний WEB-URL зберіг працездатність.** Сайт міг вибрати інший iframe, джерело могло застаріти або мати додаткові умови доступу; причину ще не доведено.

## Зміни

1. Об'єднання джерел із `J/O/M/X/L/D` за ідентичним `id` події замість відкидання дублікатів. Первинні назва матчу й стан зберігаються. Джерела дедуплікуються за URL, мовою, якістю й назвою, до 60 варіантів. Додаткові записи виду `id + _embeds` без заголовка також враховуються **лише для вже відомого матчу**.
2. У картці події кнопка **«↻ Оновити джерела цього матчу»**: без Chrome і Python отримує свіжі загальнодоступні `J/X/O` та, за наявності параметрів у HTML сторінки, `L/M`. Знову об'єднує джерела й показує числа «було → стало», «нових», «зниклих» та статуси API. У повідомлення НЕ виводяться повні URL чи значення параметрів.
3. Якщо повторний API-запит не знайшов матч або повернув 0 джерел, попередні адреси **не видаляються**, але позначаються неперевіреними.
4. «▶ Перевірити прямий HLS/DASH» як і раніше перевіряє до чотирьох унікальних URL за раз, не видає WEB-сторінку за медіопотік. Для читання WEB-сторінки джерела додано браузерний User-Agent із вибраного HTTP-профілю; Referer береться з контексту відкриття. Підписи, сесії, DRM або авторизацію не підробляє.
5. Замість великих повідомлень з JSON/URL для невдалих WEB-запитів відображає коротке `HTTP 404`, `HTTP 403` чи `таймаут`. Секретні URL не записуються у статус.
6. Виправлення канонічної адреси `/#ID` (v0.21), вбудований пошук з «Знайти / Скасувати», 56 каналів, EPG, фільтри та один JS без Bridge збережено.

## Перевірка на смартфоні

- Вимкнути v0.21 й інші дублікати STRUMYK, **повністю перезапустити Lampa**, встановити лише v0.22.
- Відкрити «Розклад» → матч із джерелами. Звернути увагу на `🎬 Джерела: N` та загальну кількість подій.
- У картці матчу натиснути **«↻ Оновити джерела цього матчу»**. Записати «старе → нове» і кількість доданих/зниклих; за потреби надіслати скріншот. Можна використати той матч Vancouver Canucks — Minnesota Wild, якщо він ще присутній.
- Далі натиснути **«▶ Перевірити прямий HLS/DASH»**. Якщо дійсний маніфест не знайдено, це НЕ означає, що в браузері відео не працює. Якщо знайшли — окремо перевірити фактичне відтворення й звук у Lampa/VLC/MX.
- Перевірити «Відкрити на сайті»: має вести до `https://strumyk.ca/#ID` конкретного матчу, а не до `/e/vip/...`.
- Коротко перевірити спорт- і TV-пошук, фільтри та EPG — вони мають працювати без зависання.

## Перевірки в коді

- Синтаксис JS: PASS.
- Одна подія в J/O/M/X/L з трьома різними варіантами джерел → одна картка, три джерела, повтори вилучаються: PASS.
- Мова/якість/назва та канонічний маршрут матчу: PASS.
- `User-Agent` для WEB-перевірки, наявність кнопки оновлення, відсутність Bridge: PASS.
- **Реальне відтворення на пристрої ще НЕ перевірено.**

Мета: чітко розрізнити (а) невраховані джерела з дублікатів API; (б) застарілі WEB-посилання; (в) обмеження прямого відтворення навіть після оновлення. Не називати помилки 404 доказом того, що сайт не відтворює подію.

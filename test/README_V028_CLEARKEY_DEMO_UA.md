# STRUMYK SPORTS v0.28 — перевірка справжнього ClearKey-відтворення у HTTPS Android Lampa

**Дата:** 22.11.2026. **Статус:** виключно дослідницький тест, не реліз відтворення спортивного контенту.

## Доведено на реальному Android користувача у v0.27

Після зміни стартового URL **встановленої Android Lampa Uncensored** на `https://bylampa.online/`:
- `location.protocol=https:`, `window.isSecureContext=true`.
- `Lampa.AndroidJS=object` — Android-міст працює.
- `navigator.requestMediaKeySystemAccess=function`, `MediaKeys=function`.
- **`ClearKey SUPPORTED`** для тестових AVC/AAC конфігурацій без ключів.
- `Lampa.Reguest().native()` -> **`JSON ARRAY 2 records`** на публічному `https://strumyk.ca/api/O.php`.
- `window.fetch()` -> `ERROR TypeError`, що може відповідати блокуванню CORS або мережі. Нативний Android HTTP при цьому працює.
- Повний каталог та EPG після переходу на HTTPS **ще не перевірялися**. Повернення 2 записів з O.php **не доводить 189 подій із J/O/M/X/L**.

Вихідний код Lampa підтверджує: `Reguest.native` викликає `Android.httpReq` **лише коли** `Platform.is('android')`; в іншому разі використовує `$.ajax` із браузерними CORS-обмеженнями. Тому в Chrome обидва мережеві тести не були незалежними нативними транспортами.

## Що нового у v0.28

На основі v0.27, **без зміни спортивних API, EPG, UI-фільтрів чи Bridge** додано окрему діагностичну сторінку з реальним тестовим відео:

`STRUMYK → ⚙ Налаштування → DASH / DRM діагностика → ▶ Публічний ClearKey DASH — тест відео`.

Тест використовує **офіційний, публічно задокументований зразок DASH-IF**, а НЕ трансляцію Strumyk:

- Маніфест з офіційного dash.js прикладу: `https://media.axprod.net/TestVectors/v7-MultiDRM-SingleKey/Manifest_1080p_ClearKey.mpd`
- Демонстраційний ClearKey приклад — саме той, що опублікований у відкритому `dash.js/samples/drm/clearkey.html`, з відкритими тестовими KID/KEY.
- Код створює ізольований `<video>` і новий `dashjs.MediaPlayer().create()` і використовує `setProtectionData({'org.w3.clearkey':{clearkeys:...}})` для **демо**, не читання ключів іншого провайдера.
- Відео запускається без звуку, має елементи Play/Pause та Stop. Стан змінюється на **`PLAYBACK_OK`** лише після прогресу часу і наявності `videoWidth`, `readyState`.
- Усі сесії очищаються при натисканні Назад/Закрити, при виході зі сторінки плагіна.
- Якщо за 18 с демонстрація не підтверджена — статус залишається **непідтверджений**. Причиною може бути CDN, CORS, кодек, DRM, autoplay. **Невдача публічного зразка не дає однозначної причини.**

### Перевірка

1. У **встановленій** Android Lampa через HTTPS встановити v0.28.
2. Перш ніж тестувати відео, відкрити **«Розклад»** і **«Телебачення»** — зафіксувати кількість подій, стан EPG (чи отримує v0.28 дані в новому HTTPS origin).
3. Відкрити **⚙ → DASH / DRM діагностика → ▶ Публічний ClearKey DASH — тест відео**.
4. Натиснути **«▶ Запустити демонстраційний DRM DASH»**. Почекати результату, перевірити фактичні рухомі кадри. Якщо потрібно, натиснути Play у самому відео.
5. Зафіксувати статус `PLAYBACK_OK` або коротку помилку, передати скріншот.
6. Для звичайної роботи зупинити тестове відео. Це не спортивний потік.

## Як трактувати

- **Демо працює, каталог працює:** EME + dash.js + нативний транспорт в одному клієнті технічно можливі. Для захищеної трансляції все одно потрібна належна DRM-конфігурація й дозволений доступ; тестові демо-ключі до Strumyk не належать.
- **Демо працює, каталог не працює:** окрема проблема Strumyk API та/або HTTP-клієнта.
- **Демо не працює, EME supported:** можливі обмеження WebView, DRM-кодека, CORS CDN, dash.js інтеграції.
- **Каталог працює, відео без DRM працює, а захищене — ні:** різні сценарії, недостатньо підстав заявляти про універсальний DRM-плеєр.

## Чого НЕ робимо

Не копіюємо справжні DRM-ключі/ліцензії/токени трансляцій, не підробляємо сесії Strumyk. Стандартний плеєр `Lampa.Player.play({url: mpd})` у дослідженому вихідному коді не має окремого інтерфейсу DRM-конфігурації. Тестовий `dash.js` екземпляр у v0.28 не змінює цей стандартний плеєр.

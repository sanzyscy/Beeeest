# STRUMYK SPORTS v0.21 — Navigation + Search Fix (22.11.2026)

## Проблеми зі скріншотів користувача
1. Матч **Vancouver Canucks — Minnesota Wild**, джерело `Premier Sports 1` в API: прямий перехід `/e/vip/...` із Lampa показує 404. Водночас на головній сторінці Strumyk цей матч відкривається та відео працює.
2. Натискання **«Пошук команд і ліг»** у v0.20 викликає `L.Input.edit()`; на смартфоні відкривається некоректний повноекранний діалог із дубльованими кнопками «Готово / Отменить», інтерфейс Lampa блокується; доводиться закривати програму.
3. Автоматичний пошук HLS у v0.20 отримує HTTP 404 для окремих WEB-джерел, навіть коли відео є на сторінці матчу. **Відтворення у плеєрі Lampa НЕ виправлене цією версією**.

## Що виправлено
- **Подія ≠ джерело.** Для всіх подій із валідним ID посилання на сам матч тепер канонічне `https://strumyk.ca/#EVENT_ID`. Шляхи `/e/vip/...` залишаються тільки в окремих `sources` як кандидати для аналізу. Подія більше не посилається на застарілий WEB embed.
- «Відкрити на сайті» у деталі, а також «Браузер» із діалогу вебджерела спортивної події, ведуть на канонічний маршрут `/#EVENT_ID` (не на WEB embed, що повертає 404).
- **Два пошуки** (спортивні події, TV): замінено `L.Input.edit()` на вбудоване в сторінку поле `<input type=search>` і кнопки **«Знайти» / «Скасувати»**. Натискання Back закриває редактор, Enter застосовує пошук, Escape скасовує. Введення не перерисовує все меню під час набору.
- v0.19 автономний каталог, профілі User-Agent/Referer, 56-канальний EPG, історія/обране, відеодіагностика v0.20 — збережені. Bridge не використовується.

## Як перевірити на Android
1. **Закрити завислу Lampa повністю** через меню останніх застосунків.
2. У «Розширеннях» Lampa вимкнути/видалити STRUMYK v0.20, залишивши інші плагіни без змін.
3. Перезапустити Lampa, встановити **тільки цей тестовий файл**:

`https://cdn.jsdelivr.net/gh/sanzyscy/Beeeest@d03ca247cd64806669e713448c75415a81164384/test/strumyk_plugin_v021_navigation_search_fix_test.js`

4. Відкрити спортивний розклад, натиснути «⌕ Пошук команд і ліг», **торкнутися поля** і ввести `Mines`, натиснути «Скасувати» (пошук не зміниться). Повторити та натиснути «Знайти» — список відфільтрується. Натиснути «Назад» під час відкритого редактора — повинен закритися редактор, а не Lampa.
5. Повторити перевірку з TV-пошуком.
6. Відкрити матч Vancouver Canucks — Minnesota Wild → «Відкрити на сайті»: тепер має відкриватися **сторінка матчу `/#ID`**, а не `/e/vip/... `. Перевірити фактичний запуск із Chrome.
7. За потреби перевірити автопошук HLS: якщо WEB-джерело відповідає 404, плагін його не підміняє неіснуючим потоком. Це окреме обмеження відеосервера.

## Межі перевірки
- Синтаксис JS: PASS.
- Офлайн-тест JSON з `pageUrl='/e/vip/...'` та `_embeds`: посилання події `/#ID`, джерело залишається окремим: PASS.
- Пошук фільтрує за назвою команди: PASS.
- Пошук не використовує `L.Input.edit` для спорт/TV, має явний Cancel/Back: PASS (статичний код); **живе введення з Android-клавіатури ще потрібно перевірити**.
- Реальне TV/спортивне відео у нативному Lampa Player: **НЕ ПІДТВЕРДЖЕНО**.
- v0.19 і v0.14 у GitHub не змінені.

### Важливий технічний висновок
Попередній `/e/vip/...` із помилкою 404 є конкретною невдалою адресою/застарілим embed. Факт робочого відео після відкриття матчу через головний сайт **не доводить** доступності автономного HLS. Діагностику відео продовжуємо окремо.

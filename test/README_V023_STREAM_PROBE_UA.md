# STRUMYK SPORTS v0.23 — перевірка потоків і захист від мертвих WEB-джерел

**Стан:** дослідницький тест. Не підтверджене відтворення в нативному Lampa Player.

Плагін v0.22 у користувача показував великий екран **404 LiteSpeed** при спробі відкрити WEB iframe матчів. Зокрема, матч Vancouver Canucks — Minnesota Wild успішно відтворювався при переході з головної сторінки Strumyk, проте окремий `/e/vip/...` URL повертав 404 навіть у Chrome. Це **різні маршрути**. Немає підстав вважати URL з каталогу надійним посиланням на відеопотік.

## Що змінено у v0.23

1. Перед показом вбудованого WEB-плеєра для старих посилань виду `https://strumyk.ca/e/vip/...` плагін перевіряє доступність HTML через HTTP-клієнт Lampa. Якщо сервер повернув 404, **не відкриває** великий 404 iframe; замість цього показує коротке повідомлення та пропонує `Відкрити на сайті` (канонічний `/#ID`).
2. HTTP-спроби знайти HLS/DASH з WEB-джерел обмежені **8 сек на один HTTP-запит** через Promise-обгортку, щоб нескінченно не чекати на повільні або мертві адреси. Сам нативний запит Lampa після такого тайм-ауту може ще завершуватись у системі, але результат ігнорується.
3. Діагностика пояснює, що невдале читання WEB-URL не доводить неможливості відтворення у браузерному плеєрі сайту.
4. Усе зі v0.22: автономний J/O/M/X/L каталог, об'єднання `_embeds` для одного матчу, кнопка оновлення джерел, заголовки UA/Referer, вбудовані пошуки, 56-канальний EPG — збережено. Робочі старі версії не змінені.

## Перевірка

1. У Lampa вимкнути попередню версію STRUMYK, повністю перезапустити застосунок; встановити v0.23.
2. У потрібному матчі вибрати WEB-джерело `Premier Sports 1` → варіант `WEB-плеєр`. Якщо `/e/vip/...` дійсно 404, замість чорної вебрамки має бути коротке повідомлення про недоступне WEB-джерело.
3. `Відкрити на сайті` має вести до канонічної сторінки `https://strumyk.ca/#ID`, не до `/e/vip/...`.
4. `↻ Оновити джерела цього матчу` → `▶ Перевірити прямий HLS/DASH`. Якщо будь-яке доступне `.m3u8` реально поверне маніфест, запустити Lampa Player і перевірити аудіо/відео. У разі невдачі записати коротке повідомлення.

## Що НЕ вирішено

- **Універсального відтворення всіх спортивних потоків поки немає.** Успішний HLS маніфест не гарантує доступність відеосегментів; більшість `_embeds` — вебсторінки, не HLS.
- Сайт Strumyk при відкритті матчу в основній сторінці може вибирати динамічний iframe і запускати власний JS. Відтворити це звичайним HTTP запитом до статичного `/e/vip/...` часто неможливо.
- Нова v0.23 **не підробляє токени, cookies, підписи, не обходить DRM і захист від стороннього програвача**. Якщо медіасервер дозволяє виключно власний сайт, для нативного відтворення потрібен передбачений провайдером доступ.

## Для глибокого аналізу

Одноразово отримати **публічний JS сайту** на телефоні (це лише файл для аналізу, не сервіс, не потрібен плагіну):

```bash
curl -fL --compressed --max-time 25 \
  -A 'Mozilla/5.0 (Linux; Android 15; Mobile) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Mobile Safari/537.36' \
  -e 'https://strumyk.ca/' \
  'https://strumyk.ca/js/strumyk-app.js' \
  -o '/storage/emulated/0/Download/strumyk-app.js'

wc -c '/storage/emulated/0/Download/strumyk-app.js'
```

Якщо виведено приблизно 49 КБ, це схоже на JS, зафіксований у попередніх браузерних звітах. Точна довжина може змінюватися. Слід перевірити файл перед передаванням і надіслати в чат, а не публікувати повний код у GitHub. Дослідження допоможе з'ясувати, як браузерний Strumyk обирає актуальне джерело.
